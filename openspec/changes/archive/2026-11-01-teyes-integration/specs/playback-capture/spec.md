# Spec Delta

## MODIFIED Requirements

### Requirement: Резервный источник — медиа-уведомления

Если плеер не публикует MediaSession, приложение MUST сохранять текст
медиа-уведомлений: заголовок, текст, `bigText`, `subText`, действия, категорию,
шаблон и наличие media session token. Для уведомлений штатного плеера
приложение MUST также сохранять ключи и примитивные значения extras и текст,
извлечённый из `contentView`/`bigContentView`, не выполняя действий
уведомления.

#### Scenario: Плеер только уведомляет

- **WHEN** плеер не отдаёт MediaSession, но показывает медиа-уведомление
- **THEN** событие `notification` содержит пакет, заголовок и текст уведомления

#### Scenario: Уведомление обновляется

- **WHEN** плеер повторно публикует то же уведомление без изменения текста и действий
- **THEN** приложение MUST NOT писать повторное событие

#### Scenario: Пустое уведомление штатного плеера

- **WHEN** уведомление штатного плеера не содержит `title`/`text`, но содержит
  пользовательский layout
- **THEN** приложение извлекает тексты `TextView` и `contentDescription` из
  `RemoteViews` и сохраняет их для диагностики; ошибка разбора не роняет службу

### Requirement: Выбор сессии «сейчас играет»

Приложение MUST выбирать один источник из нескольких доступных по приоритету:
MediaSession с названием в состоянии PLAYING, затем штатный плеер с названием
в состоянии PLAYING, затем MediaSession с названием в паузе, затем штатный
плеер с названием в паузе. При равенстве состояний MediaSession имеет
приоритет. Сессии и источники без названия MUST NOT становиться текущим
треком, но MUST попадать в полный дамп.

#### Scenario: Музыка и навигация

- **WHEN** одновременно активны музыкальный плеер и навигатор
- **THEN** текущим треком становится сессия с названием, а не служебная сессия без метаданных

#### Scenario: Яндекс.Музыка и штатный плеер

- **WHEN** Яндекс.Музыка на паузе, а штатный плеер играет
- **THEN** текущим треком становится штатный плеер, а не устаревшая пауза

## ADDED Requirements

### Requirement: Штатный плеер Teyes без MediaSession

Если штатный плеер не публикует MediaSession, приложение MUST пытаться получать
его состояние из доступных каналов в порядке приоритета: broadcast лаунчера
FYT (`titlesReceiver`/`removeReceiver`), accessibility-текст активного окна
штатного плеера, пользовательское уведомление. Приложение MUST помечать
источник каждого трека полем `source` (`media_session`, `fyt_broadcast`,
`accessibility`, `notification`) и MUST NOT выдавать данные одного источника
за данные другого.

#### Scenario: Лаунчер присылает broadcast

- **WHEN** лаунчер FYT отправляет `titlesReceiver` с названием и исполнителем
- **THEN** приложение начинает/обновляет трек с `source=fyt_broadcast`

#### Scenario: Есть только accessibility

- **WHEN** broadcast и MediaSession недоступны, пользователь открыл штатный
  плеер и включил accessibility-сервис
- **THEN** приложение использует текст окна как `source=accessibility` и
  сохраняет сырые тексты для проверки

#### Scenario: Ничего не доступно

- **WHEN** ни один канал не даёт названия
- **THEN** приложение MUST NOT создавать фиктивный трек и MUST показывать
  причину в состоянии диагностики

### Requirement: Резервный источник — broadcast лаунчера FYT

Приложение MUST принимать broadcast `titlesReceiver` с полями `title`,
`play_artist`, `play_album`, `play_path`, `play_state`, `play_total`,
`play_cur` и `source`, если он приходит. Приложение MUST игнорировать пустой
`title` и значения `Unknown`. Broadcast `removeReceiver` MUST закрывать
текущий трек штатного плеера. Приёмник MUST регистрироваться только на время
работы службы и MUST NOT требовать системных привилегий.

#### Scenario: Смена трека в штатном плеере

- **WHEN** приходит новый `titlesReceiver` с другим `title` или `play_path`
- **THEN** предыдущий трек закрывается, новый начинается с `source=fyt_broadcast`

#### Scenario: Плеер остановлен

- **WHEN** приходит `removeReceiver`
- **THEN** текущий трек штатного плеера закрывается, а не остаётся висеть

### Requirement: Необязательное чтение интерфейса штатного плеера

Приложение MAY читать текст активного окна штатного плеера через
accessibility-сервис, только если пользователь явно включил этот спецдоступ.
Сервис MUST только читать текст и MUST NOT выполнять клики, скроллинг,
ввод или изменение настроек. Приложение MUST показывать, включён ли доступ,
и MUST продолжать работать без него.

#### Scenario: Доступ не выдан

- **WHEN** accessibility-сервис выключен
- **THEN** приложение не падает и использует остальные источники

#### Scenario: Пользователь открыл плеер

- **WHEN** accessibility включён, а окно штатного плеера показывает название
- **THEN** приложение обновляет текущий трек с `source=accessibility` и
  сохраняет сырые тексты в снимке
