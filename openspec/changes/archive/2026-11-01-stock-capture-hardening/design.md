# Design

## Context

См. `proposal.md` и `docs/LOG_ANALYSIS_2026-11-01.md`. Кратко о текущем состоянии:

- `StockPlayerAccessibilityService` читает только `rootInActiveWindow` и обновляет
  `StockPlayerBridge` при смене текста; `StockPlayerBridge` считает состояние
  устаревшим через 10 минут.
- `StockPlayerParser.fromAccessibility` берёт первый кандидат из списка текстов,
  не отличает заголовок папки и строку списка от текущего трека.
- `ListeningTracker` помечает `completed` только при известной длительности;
  иначе переход внутри пакета становится `skipped`.
- `ListeningTracker.onVolume` при смене источника сбрасывает статистику трека и
  не пишет событие.
- `TeyesToolkitClient.Status.signature` включает громкость, поэтому
  `teyes_toolkit` дублирует каждый `volume_changed`.
- В `com.syu.music` нет MediaSession, медиа-уведомления и доступного broadcast;
  accessibility — единственный источник, и он видит только видимые окна.

Ограничения: Android 10, нет adb, нельзя менять штатный плеер, нельзя добавлять
разрешения и сеть, цикл опроса должен оставаться дешёвым.

## Goals / Non-Goals

**Goals:**

- Не создавать трек из заголовка папки, строки списка или переходного UI.
- Получать длительность/позицию, если UI плеера их отдаёт; иначе честно писать
  `unknown`, а не `skipped`.
- Читать видимое окно плеера в split-screen и не считать его пропавшим.
- Писать разрывы `capture_gap` и не удерживать последний трек бесконечно.
- Сохранять статистику громкости по источникам при переключении MCU ↔ audio.
- Дать диагностический материал для следующей поездки: UI-дерево, `rangeInfo`,
  список окон, статус listener.

**Non-Goals:**

- Полный фоновый захват без MediaSession, уведомления, broadcast или видимого
  окна — это невозможно в v0.
- Подмена package name, прокси-лаунчер, root, accessibility-клики, OCR или
  запись экрана.
- Свой плеер и замена штатного.
- Индекс библиотеки, Room и серверная аналитика.
- Починка старых crash-файлов: fallback экспорта уже есть в текущей сборке.

## Decisions

### 1. Уверенный разбор accessibility вместо «первого текста»

Вводится промежуточная модель окна:

- `AccessibilityWindow`: пакет, заголовок, `active`, `focused`, список узлов.
- `AccessibilityNode`: `className`, `viewIdResourceName`, `text`,
  `contentDescription`, `rangeInfo`, границы.
- `AccessibilityReading`: распознанные `title`, `artist`, `positionMs`,
  `durationMs`, `confidence`, `rejectReason`.

Правила:

- Строка `^\d+\.\s` — элемент списка, не трек.
- Заголовки `Список`, `Внутренняя память`, `Список музыки`, `USB`, `SD`,
  `Избранное` и подобные — не трек.
- Сильный кандидат: `Artist - Title.ext` без номера списка.
- Средний кандидат: `Title.ext` и следующая строка — исполнитель, не элемент
  списка/управления/времени.
- Если кандидат не уверенный, парсер возвращает `null`, а сервис не вызывает
  `StockPlayerBridge.update`; последний известный трек остаётся.
- Debounce 800 мс: сервис запоминает подпись окна, перечитывает его через
  800 мс и обновляет состояние только если подпись не изменилась.

Альтернатива «искать по `viewIdResourceName`» отвергнута до диагностики: ID
штатного плеера неизвестны, а диагностический билд соберёт их в первой поездке.
Альтернатива «эвристика по длине строки» даёт слишком много ложных срабатываний.

### 2. Время и `rangeInfo` как источник длительности

`StockPlayerParser` получает все тексты окна, включая время, и узлы с
`rangeInfo`. Порядок выбора:

1. Две и более строки времени: большее значение — `durationMs`, меньшее —
   `positionMs`.
2. Одна строка времени + `rangeInfo` с долей 0…1: позиция из времени,
   длительность вычисляется как `position / fraction`, если результат
   правдоподобен (больше позиции).
3. `rangeInfo`, где `max` явно в миллисекундах (больше 60 000): текущее значение
   — позиция, максимум — длительность.
4. Иначе оба поля `null`.

Сырые значения `rangeInfo` всегда попадают в диагностику, чтобы после поездки
уточнить формат. Ноль и длительность другого трека не подставляются.

### 3. Все видимые окна и поддержание свежести

- В `accessibility_service_config.xml` добавляется
  `flagRetrieveInteractiveWindows`; это флаг сервиса, не новое разрешение.
- Сервис перебирает `windows`, фильтрует `com.syu.music`/`com.yf.teyesspotify`,
  выбирает активное/сфокусированное окно, иначе любое видимое окно плеера.
- Пока окно плеера видимо, сервис вызывает `StockPlayerBridge.touch(nowMono)`
  даже если текст не изменился. Поэтому 15-минутный трек не истекает.
- Периодический скан раз в 2 секунды работает только при `isMusicActive` и
  включённом accessibility; при отсутствии окна скан прекращается.
- `ACCESSIBILITY_STALE_MS` снижается с 10 минут до 90 секунд. Если окно
  пропало, `StockPlayerBridge` перестаёт отдавать состояние, и `ListeningTracker`
  через свой 5-секундный grace закрывает трек как `session_lost`.
- `capture_gap` пишется один раз при переходе «окно есть → окна нет» и один раз
  при обратном переходе. Поля: `active`, `reason`, последний трек,
  `isMusicActive`, список окон.

Альтернатива «оставить 10 минут» отвергнута: при фоновом переключении треков
последний трек получает до 10 минут чужого времени. Альтернатива «закрывать
сразу» даёт ложные `session_lost` при сворачивании/раскрытии плеера.

### 4. `unknown` вместо ложного `skipped`

В `ListeningTracker.endEvent` добавляется ветка:

- если `playedMs < 3000` — `not_played` (как сейчас);
- если `durationMs == null` и `source == accessibility` — `unknown`;
- если длительность известна — `completed`/`skipped`/`interrupted` по текущим
  правилам.

`unknown` не входит в `RATED_REASONS` отчёта. Это осознанно ухудшает
наполненность `skip_rate` для штатного плеера, но убирает ложные 100% скипов.
Если диагностика покажет время/SeekBar, `unknown` станет редким.

### 5. Статистика громкости по источникам

- `VolumeReading` получает `sourceReason`:
  `mcu_available`, `mcu_unavailable`, `mcu_stale`, `mcu_error`, `audio_fallback`.
- `ListeningTracker` хранит для активного трека `Map<String, VolumeSegment>`.
  `VolumeSegment`: `start`, `low`, `high`, `end`, `max`, `changes`.
- При смене источника:
  - пишется `volume_source_changed` с `from`, `to`, `fromValue`, `toValue`,
    `fromMax`, `toMax`, `sourceReason`, `trackKey`, `title`;
  - создаётся новый сегмент, старый сохраняется;
  - ложный `volume_changed` с разницей шкал не пишется.
- `track_ended` содержит `volumeStats` по источникам; верхнеуровневые поля
  остаются для совместимости и отражают последний сегмент.
- `track_progress` содержит `volumeSource` и `volumeMax`.
- `TeyesToolkitClient.Status.signature` перестаёт включать `volume`; событие
  `teyes_toolkit` пишется только при смене `available`/`connected`/`module`/
  `error`. Значения громкости идут только через `volume_changed`.

### 6. Диагностика и отчёт

- `stock_player_ui` пишется при смене подписи окна, но не чаще раза в 2 секунды;
  в снимке `stockPlayerUi` хранится всегда. Ограничение: 60 узлов, текст 200
  символов.
- `capture_gap` — отдельное событие, не заменяет `track_ended`.
- `notificationListenerConnected` — статический статус
  `NotificationWatchService`, отдельно от `notificationAccess`.
- `report.py` добавляет `unknown` в цензурированные окончания, считает
  `capture_gap`, показывает разрез по источникам. `RATED_REASONS` не меняется.
- `docs/METRICS.md` и `docs/HEADUNIT_TEST.md` обновляются: `unknown`, разрывы,
  split-screen, проверка времени/SeekBar.

## Risks / Trade-offs

- **Ложное отклонение реального трека** → parser confidence + сохранение
  последнего состояния; при сомнении лучше не обновлять, чем создать фейк.
- **`getWindows()` не вернёт фоновое окно** → split-screen может не сработать;
  `capture_gap` покажет это, полный фон остаётся non-goal.
- **`rangeInfo` в неожиданных единицах** → используем только явные время/ms,
  сырые значения пишем в диагностику; `unknown` остаётся безопасным fallback.
- **`unknown` уменьшит `rated_plays`** → это честнее ложных скипов; после
  диагностики можно включить больше окончаний.
- **Периодический скан раз в 2 секунды** → включается только при активной музыке
  и доступном окне; при потере окна прекращается.
- **Старые отчёты не знают `unknown`** → они просто не считают такие окончания;
  новые отчёты считают их цензурированными. Формат JSONL совместим.

## Migration Plan

1. Собрать release APK с тем же package и ключом; установить поверх текущей
   версии, данные и журнал сохраняются.
2. Старые события не переписываются; новые поля и события добавляются только
   к новым записям.
3. Rollback: установить предыдущий release; старый код игнорирует новые поля.
4. Проверка: JVM-тесты, Python-тесты отчёта, `lintDebug`, `openspec validate --all`.
5. В машине: плеер на переднем плане, свёрнут, split-screen с навигатором,
   пауза, mute, естественное окончание, выключение зажигания; затем ZIP и
   `py scripts/report.py`.

## Open Questions

- Отдаёт ли UI `com.syu.music` время или `SeekBar.rangeInfo`? Ответ даст
  `stock_player_ui` в следующей поездке.
- Возвращает ли `getWindows()` окно `com.syu.music` в split-screen на этой
  прошивке? Проверяется тем же билдом.
- Есть ли у `com.syu.ms` модуль с метаданными музыки? В этом change не
  исследуется; если появится, это отдельный источник и отдельное изменение.
