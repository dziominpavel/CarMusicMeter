# Design

## Context

Сейчас `EventLog.trimOld()` при каждом старте удаляет логи старше 180 дней и
снимки сверх 600. Экспорт (`EventLog.exportTo`) забирает все файлы из `logs/`
и `snapshots/`, диапазона нет. Манифест уже содержит `schemaVersion`,
`deviceId`, `exportSeq` и контрольные суммы. Настройки хранятся в `Prefs`,
экран — `ui/ProbeScreen.kt`.

## Goals / Non-Goals

**Goals:**
- Бессрочное хранение журнала по умолчанию с защитой от переполнения.
- Выбор периода экспорта без изменения формата журнала.
- Прозрачность: видно, что и сколько хранится, и что попадёт в ZIP.

**Non-Goals:**
- Встроенная статистика на магнитоле и LAN-синхронизация — отдельные changes.
- Пережатие или переписывание старых JSONL.
- Произвольный диапазон дат в UI; пресеты покрывают основной сценарий.

## Decisions

### Один поток событий, разные политики по каталогам

Журнал остаётся единым `events-YYYY-MM-DD.jsonl`: статистические и
диагностические события лежат вместе, их нельзя разделить без переписывания
файла. Лимит 500 МБ применяется к каталогу `logs/` целиком; снимки ограничены
количеством (600), crash-файлы — 50. Альтернатива — отдельный `diag-*.jsonl` —
отклонена: новый формат и сложность экспорта ради экономии, которой при
текущих объёмах нет.

### Чистка по дате из имени, а не по `lastModified`

Дневной файл — `events-YYYY-MM-DD.jsonl`, снимок — `snapshot-YYYYMMDD-...`.
Возраст считается по этим датам. `lastModified` используется только для
crash-файлов, где даты в имени нет. Текущий день не удаляется никогда.

### Лимит объёма, а не срока, как основной предохранитель

Бессрочное хранение без ограничения объёма опасно: сбойный источник событий
может забить память. При превышении 500 МБ удаляются самые старые завершённые
дни, пока объём не вернётся под лимит. Удаление фиксируется событием
`retention_trimmed` с числом файлов, байтами и причиной. Срок хранения —
дополнительная настройка (бессрочно или N дней).

### Диапазон экспорта — фильтр на этапе сборки списка файлов

`ExportRange` (all / 90 / 30 / 7 дней) вычисляет границу по локальной дате и
фильтрует журнал по дате из имени, снимки — по префиксу имени. Crash-файлы
фильтруются по `lastModified`. Список файлов и оценка объёма считаются до
запуска SAF: если файлов нет, диалог сохранения не открывается.

### Манифест: аддитивные `range` и `coverage`

```json
"range": { "mode": "days", "days": 30, "fromMs": ..., "toMs": ... },
"coverage": { "fromMs": ..., "toMs": ... }
```

`coverage` — фактические даты файлов, попавших в ZIP. `schemaVersion`
остаётся 1: старые парсеры игнорируют новые поля, новые понимают старые
выгрузки по отсутствию `range` (трактуется как `all`).

### UI: секция «Данные» и диалог экспорта

На экране — «Хранится с …», число файлов, объём и две настройки: срок
хранения и период экспорта. Кнопка экспорта открывает диалог с пресетами и
оценкой «N файлов, M МБ». После подтверждения — обычный SAF. Во время записи
показывается состояние «Экспортирую…», чтобы не выглядело как зависание.

### Чистка запускается при старте и при смене настроек

Периодическая чистка не нужна и создаёт гонки с экспортом. При смене срока
или лимита чистка выполняется сразу в IO-корутине; текущий день защищён.

## Risks / Trade-offs

- **500 МБ может удалить историю раньше, чем пользователь ожидает** → в UI
  видно «хранится с …», событие `retention_trimmed` объясняет причину; перед
  повышением лимита можно выгрузить всё.
- **Сбитые часы магнитолы** → дата берётся из имени файла; файлы с
  неразборчивым именем не удаляются автоматически.
- **Долгий экспорт большой истории** → до SAF показывается объём; в UI
  состояние «Экспортирую…»; ZIP пишется потоково, без чтения всех файлов в
  память.
- **Снимки и crash-файлы не входят в лимит 500 МБ** → их объём ограничен
  количеством (примерно единицы мегабайт); при необходимости лимит можно
  распространить позже.
- **Старые выгрузки без `range`** → читаются как `all`, отчёт на ПК это уже
  допускает.

## Migration Plan

Миграции данных нет: существующие файлы остаются, новая политика применяется
при следующем старте. Значения по умолчанию: хранение бессрочное, лимит
500 МБ, экспорт всей истории. Откат — вернуть прежние константы 180/600;
формат журнала и манифеста совместим.

## Open Questions

Нет. Произвольный диапазон дат и раздельная политика для диагностических
событий отложены до появления реальных объёмов.
