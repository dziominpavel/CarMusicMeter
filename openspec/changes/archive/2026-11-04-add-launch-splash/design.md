# Design

## Context

См. `proposal.md` — Why. Что важно для реализации:

- `MainActivity.onCreate` уже запускает службу сбора до `setContent`; экран выбирается
  строкой `screenName` (`DASHBOARD`/`DIAGNOSTICS`/`SETTINGS`), отдельной Activity на
  экраны нет.
- `AutostartActivity` — невидимый трамплин с прозрачной темой, его трогать нельзя.
- `minSdk 29`, `targetSdk 36`: `RenderEffect`/`Modifier.blur` недоступны (API 31+),
  `MotionDurationScale` Compose учитывает сам.
- Фон приложения — плоский `#070B0E`, акцент — `#5BE49B`. Иконка — растровый неон
  640×640 с запечённым фоном и градиентами.
- Готовый клип: 1024×1024, 24 fps, 1.04 с, H.264, без звука, 256 КБ.

## Goals / Non-Goals

**Goals:**

- Медальон с видео-анимацией на холодном старте, без задержки сбора и данных.
- Ноль новых зависимостей и разрешений; +256 КБ к APK.
- Предсказуемое поведение на слабом Android 10 без GPU-фокусов.

**Non-Goals:**

- Векторная/Lottie/Rive версия, замена иконки и вордмарка.
- Звук (запрещён правилами проекта), анимация содержимого пульта, несколько
  вариантов заставки.

## Decisions

### 1. Видео, а не вектор

Текущий арт — растровый рендер со стеклом, свечением и градиентами. `VectorDrawable`
не поддерживает фильтры и blur, а `RenderEffect` на API 29 отсутствует: векторная
версия стала бы заметно площе. Lottie не конвертирует растр и добавляет зависимость.
Рукописный Compose дал бы другой рисунок. Итог: клип уже готов, весит меньше исходной
PNG-иконки (256 КБ против 490 КБ) и сохраняет фактуру.

Альтернатива «перерисовать в вектор» отложена: меняет визуальный язык, а не только
технику.

### 2. Круг — заливка углов фоном, а не клип видео-слоя

`SurfaceView` не обрезается, а клип `TextureView` через Compose-слой зависит от
поведения вендора. Так как фон плоский, надёжнее нарисовать поверх видео Path
«прямоугольник минус круг» цветом `#070B0E`. Работает на любом API и любом
декодере, стоит один draw-вызов.

### 3. Оверлей поверх готового экрана, а не отдельная Activity

Заставка — `Box { currentScreen(); if (introVisible) LaunchSplash() }` в `MainActivity`.
Данные и служба стартуют как раньше, к кроссфейду пульт уже отрисован. Отдельная
Activity добавила бы второй жизненный цикл, мигание между окнами и риск повторного
запуска службы.

### 4. Гейт: один показ на процесс

Условие — процессный флаг `LaunchSplashGate`: заставка играет один раз за жизнь
процесса. Поворот экрана и возврат из другого приложения процесс не перезапускают,
поэтому анимация не повторяется. Вытеснение процесса системой — новый процесс,
заставка играет снова.

`savedInstanceState` для этого не годится: система восстанавливает task вместе
с состоянием даже после force-stop, и гейт по нему глушил бы заставку при обычном
перезапуске из лаунчера.

### 5. Тайминг

Клип 1.04 с → удержание последнего кадра 350 мс → кроссфейд 250 мс ≈ 1.64 с.
Сторожевой таймер 1.8 с завершает заставку, даже если колбэк декодера не пришёл.

### 6. Свечение и палитра

Зелёный радиальный градиент `#5BE49B` за медальоном: вводит акцентный цвет до
появления UI и сшивает фиолетовый арт с зелёным пультом. Блюр не используем —
градиент с плавным alpha-спадом даёт тот же вид на API 29.

### 7. Фолбэк на статичный кадр

Под видео-слоем всегда лежит PNG-кадр медальона (`drawable-nodpi/`): пока декодер
не отдал первый кадр, виден он; при ошибке воспроизведения он остаётся и заставка
всё равно корректно завершается. Это снимает и «чёрную вспышку», и разницу
размеров с системным splash.

## Risks / Trade-offs

- **Задержка первого кадра декодера на CC3 (100–300 мс)** → статичный PNG под
  видео-слоем и сторожевой таймер; на магнитоле проверяется отдельно.
- **`MediaPlayer` на некоторых прошивках не отдаёт кадр или падает** → ошибка
  ловится, заставка деградирует до статичного кадра и завершается.
- **24 fps на 60 Гц** → движение стрелки может выглядеть чуть ступенчато; клип
  короткий, интерполяция не оправдана.
- **Запечённый `TEYES CC3` и отсутствие паузы в исходнике** → пауза добавляется
  кодом (удержание последнего кадра); текст принят осознанно, убирается только
  перерисовкой.
- **Квадрат 1024×1024 на телефоне** → медальон занимает ~60% высоты (≈648 px при
  1080p), апскейл минимальный.
- **Память на декод** → видео-слой освобождается сразу после заставки, чтобы не
  держать буфер в фоне.

## Migration Plan

Обратной совместимости не требуется: ассет новый, поведение добавляется. Откат —
удалить оверлей и ассет, остальное не затронуто.
