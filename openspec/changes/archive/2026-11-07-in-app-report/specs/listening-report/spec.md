# Spec Delta

## Purpose

Показывать владельцу готовый отчёт по прослушиваниям прямо на устройстве и
упаковывать его в ZIP для ПК и ИИ, не требуя Python и второй программы.

## ADDED Requirements

### Requirement: Отчёт на устройстве

Приложение MUST предоставлять экран отчёта, доступный с главного экрана за один
тап. Экран MUST работать офлайн и MUST NOT требовать ПК, Python или вторую
программу. Периоды MUST быть 7, 30, 90 дней и вся история; выбранный период
MUST сохраняться между запусками.

#### Scenario: Открытие отчёта

- **WHEN** пользователь нажимает «Анализ» на главном экране
- **THEN** открывается отчёт с выбранным периодом, сводкой и списками треков

#### Scenario: Офлайн

- **WHEN** на устройстве нет сети
- **THEN** отчёт открывается и считает метрики по локальным фактам

#### Scenario: Период запоминается

- **WHEN** пользователь выбрал 30 дней и перезапустил приложение
- **THEN** отчёт снова открывается за 30 дней

### Requirement: Сводка и топ

Отчёт MUST показывать прослушанное время, число прослушиваний, поездок и
треков, топ по числу прослушиваний и антитоп по доле скипов. Антитоп MUST
учитывать только треки с минимум тремя оценёнными окончаниями. Треки с малым
числом данных MUST быть помечены.

#### Scenario: Сводка

- **WHEN** за период есть 42 прослушивания и 6 поездок
- **THEN** отчёт показывает те же числа и суммарное прослушанное время

#### Scenario: Топ

- **WHEN** один трек имеет больше прослушиваний, чем остальные
- **THEN** он стоит первым в списке «Слушал чаще»

#### Scenario: Антитоп

- **WHEN** у трека только два оценённых окончания
- **THEN** он не попадает в антитоп и помечается «мало данных»

### Requirement: Качество данных

Отчёт MUST показывать покрытие длительности, позиции и громкости, число
разрывов сбора, восстановленных и открытых прослушиваний, непроверенных дат и
долю history-фактов. Показатели MUST быть отделены от основных метрик и MUST
NOT трактоваться как ноль.

#### Scenario: Неполные данные

- **WHEN** у части прослушиваний нет длительности
- **THEN** отчёт показывает долю покрытия, а не нулевую длительность

#### Scenario: Непроверенная дата

- **WHEN** в истории есть факты с `clockVerified=false`
- **THEN** они показаны отдельной строкой и не расширяют период в прошлое

#### Scenario: История и live

- **WHEN** в отчёте есть и live, и history-факты
- **THEN** блок качества показывает их число раздельно

### Requirement: Детали трека

Отчёт MUST показывать по треку число прослушиваний, прослушанное время,
`completion`, долю скипов, среднюю точку скипа, громкость, перемотки и
последнюю дату. Детали MUST содержать причины попадания в антитоп и список
последних прослушиваний.

#### Scenario: Детали трека

- **WHEN** пользователь нажимает на трек
- **THEN** открываются метрики трека и список его прослушиваний

#### Scenario: Причина антитопа

- **WHEN** трек попал в антитоп
- **THEN** детали объясняют причину: «3 из 5 — скип», «в среднем 24%»

#### Scenario: Мало данных

- **WHEN** у трека меньше трёх оценённых окончаний
- **THEN** детали показывают подсказку о недостатке данных

### Requirement: Кандидаты

Отчёт MUST показывать кандидатов «послушать ещё» по правилу: не менее трёх
оценённых, длительность не меньше 60 с, `skip_rate` не ниже 0.6,
`completion` не выше 0.4, ни одного `completed`. Без индекса коллекции
кандидат MUST быть помечен «локальность неизвестна» и MUST NOT предлагаться к
удалению.

#### Scenario: Кандидат

- **WHEN** трек удовлетворяет всем условиям
- **THEN** он попадает в список с причинами и оговоркой «не приговор»

#### Scenario: Без индекса коллекции

- **WHEN** приложение не знает, локальный трек или стриминг
- **THEN** кандидат помечен «локальность неизвестна» и действие удаления
  отсутствует

#### Scenario: Мало данных

- **WHEN** у трека меньше трёх оценённых окончаний
- **THEN** он не попадает в кандидаты

### Requirement: Производительность и загрузка

Отчёт MUST считаться в фоне и MUST NOT блокировать цикл захвата. Первый разбор
истории MUST показывать прогресс; повторное открытие MUST использовать кэш
фактов. Ошибка разбора MUST NOT ронять приложение и MUST показываться с
возможностью повторить.

#### Scenario: Первый разбор истории

- **WHEN** отчёт открывается впервые после обновления
- **THEN** показывается прогресс по дням, а захват продолжает писать события

#### Scenario: Повторное открытие

- **WHEN** кэш фактов уже прогрет
- **THEN** отчёт открывается без повторного разбора

#### Scenario: Ошибка разбора

- **WHEN** журнал содержит повреждённую строку
- **THEN** отчёт показывает ошибку и кнопку «Повторить», приложение не падает

### Requirement: Отчёт в ZIP

Экспорт MUST добавлять в ZIP `tracks.csv`, `report.html` и
`ai-prompt.md` за выбранный диапазон. `report.html` MUST быть
самодостаточным и открываться без сети. `ai-prompt.md` MUST содержать
сводку, топ/антитоп, качество и инструкцию не выдумывать числа. Манифест MUST
содержать блок `report`.

#### Scenario: ZIP с отчётом

- **WHEN** пользователь выгружает ZIP за 30 дней
- **THEN** внутри есть `tracks.csv`, `report.html`, `ai-prompt.md`, а в
  манифесте — блок `report` с периодом и числом треков

#### Scenario: HTML без сети

- **WHEN** `report.html` открывают на ПК без интернета
- **THEN** отчёт отображается целиком, без внешних ресурсов

#### Scenario: Промпт для ИИ

- **WHEN** пользователь открывает `ai-prompt.md`
- **THEN** видит готовый бриф с числами, оговорками о качестве и заданием

### Requirement: Совпадение с эталоном

Метрики отчёта MUST совпадать с `scripts/report.py` на тех же фактах: число
прослушиваний, оценённых и цензурированных, `playedMs`, `completion`,
`skip_rate`. Расхождения MUST быть задокументированы и покрыты тестом;
`report.py` остаётся эталоном.

#### Scenario: Совпадение

- **WHEN** отчёт и `report.py` считают один и тот же архив
- **THEN** ключевые числа совпадают в пределах задокументированных допусков

#### Scenario: Расхождение

- **WHEN** реализации расходятся больше допуска
- **THEN** parity-тест падает и показывает различия по трекам

### Requirement: Отсутствие сети

Приложение MUST NOT добавлять разрешение `INTERNET` и MUST NOT отправлять
историю прослушиваний. `ai-prompt.md` MUST быть единственным мостом к ИИ:
пользователь сам передаёт его на ПК или в чат. Отчёт MUST работать без сети.

#### Scenario: Нет INTERNET

- **WHEN** проверяется манифест приложения
- **THEN** разрешения `INTERNET` нет

#### Scenario: ИИ на ПК

- **WHEN** пользователь хочет анализ с ИИ
- **THEN** приложение не делает сетевых запросов, а отдаёт `ai-prompt.md`

#### Scenario: Офлайн

- **WHEN** сети нет
- **THEN** отчёт и экспорт работают
