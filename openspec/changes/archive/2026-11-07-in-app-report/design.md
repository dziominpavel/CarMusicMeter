# Design

## Context

- `play-facts` даёт слитые `PlayRecord` за любой период и кэш истории.
- Магнитола Teyes CC3: тёмный экран 1024×600, слабый SoC, управление пальцем;
  отчёт смотрят на стоянке, но он не должен мешать захвату.
- `scripts/report.py` уже содержит эталонные метрики и `--json`; его можно
  использовать как oracle.
- Сети и `INTERNET` нет и не будет; ИИ живёт на ПК.
- `AppScreen` — простая навигация строкой, `DashboardScreen` уже адаптивный
  (wide/compact), `ListeningRepository` — пример state-holder.

## Goals / Non-Goals

**Goals:**

- Ответить в машине: сколько слушал, что чаще, что скипаю, можно ли верить.
- Не требовать ПК, Python и второй программы.
- Отдавать в ZIP готовый отчёт и промпт для ИИ.
- Совпадать с `report.py` по числам.

**Non-Goals:**

- Матчинг с коллекцией, LUFS, «ни разу не играло» — следующий change.
- Полная таблица на 3000 треков в машине: она в `report.html`/`tracks.csv`.
- Сеть, AI, облако.
- Замена `report.py`: он остаётся эталоном и инструментом ПК.

## Decisions

### D1. Отчёт читает факты, а не события

`ReportRepository` получает `List<PlayRecord>` из `PlaySource` и не знает
про `events-*.jsonl`. Это делает отчёт быстрым и снимает с UI поправку
часов, склейку и дедуп. History-факты уже помечены `origin=history`.

### D2. Движок метрик — чистый Kotlin

Новый пакет `data/metrics/` без Android: `ReportPeriod`, `MetricsEngine`,
`ReportModel`, `TrackMetrics`, `QualitySummary`. Вход — `List<PlayRecord>`
и период; выход — модель для UI и рендереров. Формулы — из
`docs/METRICS.md`; `report.py` — эталон.

Почему не считать в UI: одни и те же числа нужны экрану, HTML и CSV; движок
тестируется JVM-тестами и сверяется с Python.

### D3. UI: выводы, а не таблица

Экран отчёта — вертикальный `LazyColumn` с крупными карточками:

1. Период: чипы 7 / 30 / 90 / всё.
2. Три числа: прослушано, прослушиваний, поездок.
3. Полоса качества: «96% громкость · 88% длительность · 0 разрывов» с
   переходом в детали.
4. Две колонки на wide / две секции на compact: «Слушал чаще» и «Пропускал
   чаще» по 5 строк.
5. «Кандидаты» — 3 строки и «все».
6. «Все треки» и «Сохранить отчёт в ZIP».

Детали трека: заголовок, 4 числа, громкость, причина антитопа, последние
прослушивания. Качество: покрытие, разрывы, restored/open, непроверенные,
live/history. Все треки: `LazyColumn` без поиска; полная таблица — в HTML/CSV.

Почему не таблица: в машине нужен ответ, а не 3000 строк; полный срез уже
уезжает в ZIP.

### D4. Качество данных — первый класс

`QualitySummary` считает: покрытие длительности, позиции, MCU-громкости,
число `capture_gap`, restored, open, unverified, history/live. Нулевое
покрытие MUST NOT подменяться нулём в метриках: «неизвестно» показывается
прочерком и процентом. Это защищает от ложных выводов по неполным данным.

### D5. Кандидаты без индекса коллекции

Правило из `METRICS.md` применяется к фактам, но без `library.db` нельзя
отличить локальный файл от стриминга. Поэтому раздел называется «послушать
ещё», каждый кандидат помечен «локальность неизвестна», кнопки удаления нет.
Настоящие кандидаты появятся после импорта индекса коллекции.

### D6. Экспорт: три производных артефакта

`ReportExporter` по модели строит:

- `tracks.csv` — агрегаты по трекам (UTF-8 BOM, CRLF);
- `report.html` — один файл, inline CSS, без JS и внешних ресурсов; тёмная
  или светлая тема для чтения на ПК, экранирование title/artist;
- `ai-prompt.md` — сводка, топ/антитоп, качество, определения и задание
  «не выдумывай числа».

`EventLog.exportTo` (из `play-facts`) принимает сгенерированные записи,
считает SHA-256 и добавляет их в `files[]`. Манифест получает `report`:
период, число треков, `generatedAt`, версия отчёта.

Почему HTML генерирует приложение, а не ПК: ZIP должен быть самодостаточным;
открыть его можно на ПК или телефоне без Python. Почему без JS: меньше
поверхности, работает в старом браузере, не нужен CDN.

### D7. Фон, прогресс, отмена

`ReportRepository` работает в `Dispatchers.IO` (чтение/разбор) и
`Dispatchers.Default` (метрики), отдаёт `StateFlow<ReportUiState>`:
`Loading(progress)`, `Ready(model)`, `Empty`, `Error(message)`. Первый
разбор истории показывает «3 из 7 дней»; повторное открытие использует кэш.
Захват не блокируется: отчёт только читает файлы, запись идёт в отдельных
корутинах; при уходе с экрана загрузка отменяется.

### D8. Никакой сети и AI в приложении

`INTERNET` не добавляется. `ai-prompt.md` — единственный мост: пользователь
сам копирует его в чат на ПК. Это сохраняет обещание «данные никуда не
уходят» и не требует ключей.

### D9. Документы и политика

`AGENTS.md`: «лёгкая агрегация по `plays` — на устройстве; индекс, LUFS,
матчинг и глубокие отчёты — на ПК». `README`: приложение собирает и
показывает отчёт, ZIP — для ПК и ИИ. `ROADMAP`: экран статистики переезжает
из v2 в v1. `METRICS.md`: приложение — первый потребитель, `report.py` —
эталон. `CHANGELOG`: пользовательский блок.

## UI states

- **Loading:** прогресс и «Разбираю историю… N из M дней».
- **Ready:** отчёт.
- **Empty:** «За этот период нет прослушиваний» и чипы периода.
- **Error:** текст, «Повторить», кнопка назад.
- **Partial:** в качестве данных строка «часть истории восстановлена».

## Flow

```
PlaySource ──► MetricsEngine ──► ReportModel
                                   ├─► ReportScreen
                                   ├─► TrackDetailScreen
                                   ├─► QualityScreen
                                   └─► ReportExporter ──► tracks.csv
                                                          report.html
                                                          ai-prompt.md
                                                          manifest.report
```

## Testing

- JVM: `MetricsEngine` на golden-наборе (completed, skipped, unknown,
  restored, open, unverified), `ReportPeriod`, `QualitySummary`.
- Golden: мини-архив и ожидаемый `tracks.csv`/`report.json`.
- Parity: `report.py --json` против Kotlin на одних фактах; допуски
  задокументированы.
- UI: пустое состояние, загрузка, ошибка, малый экран; запуск на телефоне.
- Устройство: отчёт на 1024×600, открытие из машины, экспорт и открытие
  `report.html` на ПК.
- Регрессия: захват не падает и не теряет события при открытом отчёте.

## Trade-offs

- Метрики дублируются в Kotlin и Python — плата за офлайн; закрывается parity.
- В машине нет полной таблицы — сознательно; полный срез в HTML/CSV.
- HTML без JS — проще и надёжнее, но без интерактивной сортировки.
- Первый разбор истории — секунды; кэш и прогресс скрывают это.
- Кандидаты без коллекции — осторожная формулировка вместо ложного «удалить».
