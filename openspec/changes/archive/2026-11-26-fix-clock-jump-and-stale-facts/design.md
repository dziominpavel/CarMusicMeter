# Design

## Context

Сейчас поправка часов есть только в разборе истории: `PlayBuilder` пересчитывает
`startedAt`/`endedAt` через `clock_changed` и `bootId`/`monoMs`. Live-факт
пишется в момент закрытия: `startedAt` берётся из `Active.startedAtWallMs` как
есть, `clockVerified` — из `ClockStatus.verified` на момент закрытия, а
`EventLog.playFileFor` кладёт факт в файл дня по `startedAt`. Если трек начался
до скачка, получается факт с `startedAt` 2023 года, `endedAt` 2026-го и
`clockVerified=true`.

Открытое прослушивание разбор строит для каждого `track_started` без
`track_ended`; в выгрузке от 26.11 пять таких стартов остались «открытыми» на
11-03…11-06. Слияние схлопывает только одинаковые `playId`, поэтому два
закрытия одного трека (старый и новый процесс) дают два факта.

## Goals / Non-Goals

**Goals:** реальный `startedAt` у live-факта после скачка; признак
достоверности по старту; страховка для уже записанных фактов; закрытие
«висящих» открытых; один факт на одно прослушивание.

**Non-Goals:** перезапись уже записанных фактов (отдельное решение);
синхронизация системных часов магнитолы; правки `report.py`;
метрики «разрывов» и «Неизвестно» из обзора выгрузки.

## Decisions

- **Сдвиг в момент скачка, а не при закрытии.** `raiseMs`/`dropMs` считаются как
  `wallMs - startedAtWallMs` в момент изменения громкости (`ListeningTracker`),
  поэтому сдвинуть старт при закрытии недостаточно — места подъёма останутся
  в 2023 году. `Active` получает `startedMonoMs`; `logClockChange` после
  `ClockStatus.onClockChanged` вызывает `tracker.onClockChanged(monoBefore, drift)`,
  и трекер сдвигает `startedAtWallMs` и уже записанные `raiseMs`/`dropMs` на
  `drift`, если старт был до скачка (`startedMonoMs <= monoBefore`). Второй и
  последующие скачки применяются к тем же трекам по тому же правилу.
- **`clockVerified` берётся из времени старта.** `Active` хранит признак
  `startedVerified`; факт достоверен, если старт был при проверенных часах или
  старт исправлен поправкой. Закрытие уже не может «повысить» факт.
- **Страховка на чтении с окном в сутки.** `PlaySource` после слияния помечает
  `clockVerified=false` факт, у которого `startedAt > endedAt` или
  `endedAt - startedAt > 24 ч`. Сутки выбраны потому, что `PlaySource` —
  чистый слой без даты сборки APK, а реальные прослушивания в выгрузке
  укладываются в 3 часа (максимум паузы внутри трека — ~3 ч). Файлы не
  перезаписываются: флаг живёт в отчёте и в экспорте.
- **Открытым остаётся только текущее прослушивание.** Решает слияние
  (`PlaySource`), а не разбор одного файла: файл не видит соседние дни, поэтому
  «последний старт» в нём — не то же, что «играет сейчас». Запись из открытого
  файла (`origin=live`) авторитетна; если её нет, остаётся поздний по времени
  старт. Остальные открытые закрываются как `session_lost` с `playedMs` и
  позицией из `track_progress`. Такой факт не входит в оценку окончаний, но его
  время попадает в `playedMs` и качество данных.
- **Старт и окончание склеиваются по `playId`.** После сдвига часов
  `track_ended.startedAt` уже исправлен, а `track_started.ts` — ещё нет, и
  поиск по паре «bootId + trackKey + время» перестаёт находить старт. Поэтому
  разбор ищет старт по `playId` (с откатом на прежний ключ), а `startedAt`
  берёт из неисправленного `ts` старта — поправка применяется ровно один раз.
- **Дедупликация в два ключа.** Сначала `playId` (он ловит пару «старт без
  конца в одном файле + окончание в следующем»), затем `trackKey`+`startedAt`
  (разные `playId` у закрытий из разных процессов). Приоритет: live → закрытая
  запись → не-restored → меньший `endedAt`. `PlayBuilder.VERSION` повышается,
  чтобы кэш дней пересобрался с новым правилом.

## Risks / Trade-offs

- Прослушивание, реально висящее на паузе больше суток, будет помечено как
  недостоверное → порог можно уточнить полем в схеме, но в текущих данных
  таких нет.
- Сдвиг старта увеличивает `playedMs`-окно: `endedAt - startedAt` станет
  меньше, но `playedMs` не меняется — расхождение только в длительности пауз.
- Закрытие «висящих» как `session_lost` не добавит их в рейтинг окончаний —
  это честно, причина окончания неизвестна.
- Дедупликация может скрыть настоящий повтор трека → ключ включает
  `startedAt` с точностью до мс, совпадение исключено.
- Повышение версии builder'а сбрасывает кэш всех дней: первый отчёт после
  обновления дольше на несколько секунд.
- История всё ещё собирается по одному файлу: прослушивание, начатое до
  полуночи и закрытое после, склеивается по `playId`, но факт из второго файла
  остаётся без подтверждённой даты. Это ограничение разбора на уровне архива,
  а не этой правки.

## Migration Plan

- Данные не мигрируют: обновление APK, страховка на чтении применяется к старым
  фактам при каждом отчёте и экспорте.
- Откат — предыдущий APK; записанные файлы не меняются.
- Проверка на выгрузке от 26.11: период отчёта начинается 3 ноября, фактов с
  датой 2023 нет, открытых — один (текущий трек), дублей «Good Enough» и
  «Капкан» нет.
