# Spec Delta

## MODIFIED Requirements

### Requirement: Экспорт ZIP

Приложение MUST экспортировать журнал, снимки, факты прослушиваний и
`manifest.json` в ZIP. Факты MUST быть слитыми за выбранный диапазон и MUST
включать `plays/plays.jsonl`, `plays/plays.csv`, `DATA_DICTIONARY.csv` и
`SCHEMA.md`. Если системный диалог сохранения доступен, приложение MUST
использовать `ACTION_CREATE_DOCUMENT`. Если обработчика нет, приложение MUST
сохранить ZIP в `Downloads/CarMusicMeter` через `MediaStore`, MUST NOT
падать и MUST сообщить путь к файлу. Экспорт MUST NOT зависеть от прав на
запись по конкретному пути.

#### Scenario: Флешка только для чтения

- **WHEN** пользователь выбирает место на NTFS-флешке, доступной только для чтения
- **THEN** экспорт идёт через SAF и завершается успешно либо показывает понятную ошибку

#### Scenario: Нет системного диалога

- **WHEN** на магнитоле нажата кнопка «Экспорт логов», а обработчик
  `ACTION_CREATE_DOCUMENT` отсутствует
- **THEN** приложение не падает, сохраняет ZIP в `Downloads/CarMusicMeter`
  и показывает путь к файлу

#### Scenario: Телефон с SAF

- **WHEN** экспорт запускается на телефоне, где системный диалог есть
- **THEN** приложение использует обычный выбор файла и не пишет в Downloads
  без выбора пользователя

#### Scenario: Поделиться архивом

- **WHEN** ZIP сохранён через запасной путь
- **THEN** пользователь может открыть системное меню «Поделиться» для этого файла

#### Scenario: Факты в ZIP

- **WHEN** пользователь выгружает историю, по которой уже есть факты
- **THEN** в ZIP есть `plays/plays.jsonl`, `plays/plays.csv`,
  `DATA_DICTIONARY.csv` и `SCHEMA.md`, а число строк совпадает с манифестом

#### Scenario: Открытый факт

- **WHEN** выгрузка запускается, пока трек играет
- **THEN** в `plays/plays.jsonl` есть запись с `open=true`, а в манифесте
  она учтена отдельно от закрытых

### Requirement: Манифест выгрузки

Каждый ZIP MUST содержать `manifest.json` с версией формата (`schemaVersion`),
стабильным `deviceId`, номером выгрузки (`exportSeq`), временем выгрузки,
версией приложения, моделью устройства и списком файлов с путём, размером и
SHA-256. Манифест MUST содержать `range`, `coverage`, `logs[]` с числом
событий и непроверенных по каждому журналу и `plays` с
`playsSchemaVersion`, числом live/history/open/rated/censored и границами
времени. `coverage` MUST считаться по фактическим временам событий, а не по
именам файлов. Манифест MUST позволять склеивать выгрузки без разбора журнала.

#### Scenario: Повторная выгрузка

- **WHEN** пользователь экспортирует журнал дважды
- **THEN** вторая выгрузка имеет больший `exportSeq` при том же `deviceId`,
  а файлы сопоставляются по пути и контрольной сумме

#### Scenario: Архив переименован

- **WHEN** ZIP переименовывают при переносе на ПК
- **THEN** по `manifest.json` видно устройство, номер и диапазон выгрузки

#### Scenario: Выгрузка за 30 дней

- **WHEN** пользователь выбирает пресет «30 дней»
- **THEN** в манифесте `range.mode` равен `days`, а `coverage` содержит
  фактические даты файлов, попавших в архив

#### Scenario: В журнале есть непроверенное время

- **WHEN** в выгрузку попал `events-unverified.jsonl` и журнал за 2026-11-04
- **THEN** `coverage` начинается с 2026-11-04, а не с даты из имени
  непроверенного файла, и `logs[]` показывает число событий с
  `clockVerified=false` в каждом файле

#### Scenario: Факты в манифесте

- **WHEN** ZIP содержит `plays/plays.jsonl`
- **THEN** `manifest.plays` содержит `playsSchemaVersion`, число live,
  history, open, rated и censored, а границы времени совпадают с файлом

#### Scenario: Старая выгрузка

- **WHEN** архив собран версией формата 1, где `logs[]` и `clockVerified` нет
- **THEN** отчёт продолжает читать такую выгрузку и не падает

### Requirement: Диапазон экспорта

Приложение MUST поддерживать выгрузку за всю историю (по умолчанию) и за
последние 90, 30 или 7 дней. Диапазон MUST применяться к журналу, снимкам и
фактам прослушиваний по `startedAt`; открытый факт MUST включаться в любой
диапазон. Если за выбранный период нет ни файлов, ни фактов, приложение MUST
NOT создавать ZIP и MUST показать понятное сообщение. Перед экспортом
приложение MUST показывать число файлов и оценку объёма.

#### Scenario: По умолчанию вся история

- **WHEN** пользователь запускает экспорт, не меняя период
- **THEN** в ZIP попадают все файлы, которые есть в хранилище, и все факты

#### Scenario: Пресет 30 дней

- **WHEN** выбран период «30 дней»
- **THEN** в ZIP попадают только журнал, снимки и факты за последние 30 дней,
  а открытый факт включён

#### Scenario: Пустой период

- **WHEN** за выбранный период нет ни одного файла и ни одного факта
- **THEN** ZIP не создаётся, пользователь видит сообщение «нет данных
  за период»

#### Scenario: Оценка перед экспортом

- **WHEN** пользователь открывает экспорт
- **THEN** приложение показывает число файлов и примерный объём
