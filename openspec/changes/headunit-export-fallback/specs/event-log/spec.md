# Spec Delta

## MODIFIED Requirements

### Requirement: Снимок диагностики

Приложение MUST сохранять JSON-снимок по кнопке и MUST сохранять снимок
автоматически при старте каждого трека. Снимок MUST содержать версию приложения,
модель устройства, версию Android, состояние доступа к уведомлениям, громкость,
все аудиопотоки, `isVolumeFixed`, `audioMode`, `isMusicActive`, аудиовыходы,
все активные сессии и последние уведомления с признаком `mediaLike`.

#### Scenario: Первый трек в машине

- **WHEN** штатный плеер начал играть первый трек
- **THEN** рядом с журналом появляется снимок `snapshot-*-track_started.json`

#### Scenario: Громкость на Teyes

- **WHEN** пользователь делает снимок при громкости 4 на панели
- **THEN** снимок содержит значения и максимумы всех аудиопотоков и
  `isVolumeFixed`, даже если `STREAM_MUSIC` показывает 25/25

#### Scenario: Неизвестное уведомление

- **WHEN** локальный плеер публикует уведомление без медиашаблона
- **THEN** оно попадает в снимок с `mediaLike = false`, но не создаёт событие
  `notification` в журнале

### Requirement: Экспорт ZIP

Приложение MUST экспортировать журнал, снимки и `manifest.json` в ZIP. Если
системный диалог сохранения доступен, приложение MUST использовать
`ACTION_CREATE_DOCUMENT`. Если обработчика нет, приложение MUST сохранить ZIP
в `Downloads/CarMusicMeter` через `MediaStore`, MUST NOT падать и MUST сообщить
путь к файлу. Экспорт MUST NOT зависеть от прав на запись по конкретному пути.

#### Scenario: Флешка только для чтения

- **WHEN** пользователь выбирает место на NTFS-флешке, доступной только для чтения
- **THEN** экспорт идёт через SAF и завершается успешно либо показывает понятную ошибку

#### Scenario: Нет системного диалога

- **WHEN** на магнитоле нажата кнопка «Экспорт логов», а обработчик
  `ACTION_CREATE_DOCUMENT` отсутствует
- **THEN** приложение не падает, сохраняет ZIP в `Downloads/CarMusicMeter`
  и показывает путь к файлу

#### Scenario: Телефон с SAF

- **WHEN** экспорт запускается на телефоне, где системный диалог есть
- **THEN** приложение использует обычный выбор файла и не пишет в Downloads
  без выбора пользователя

#### Scenario: Поделиться архивом

- **WHEN** ZIP сохранён через запасной путь
- **THEN** пользователь может открыть системное меню «Поделиться» для этого файла

## ADDED Requirements

### Requirement: Диагностика запуска службы

Приложение MUST писать событие `service_started` с источником запуска:
`manual`, `boot` или `notification`. Событие MUST позволять отличить запуск
после загрузки от ручного и от запуска по уведомлению.

#### Scenario: Запуск после загрузки

- **WHEN** система прислала `BOOT_COMPLETED` и служба стартовала
- **THEN** в журнале есть `boot_received` и `service_started` с
  `source = boot`

#### Scenario: Ручной запуск

- **WHEN** пользователь нажал «Запустить службу»
- **THEN** в журнале есть `service_started` с `source = manual`

#### Scenario: Запуск по уведомлению

- **WHEN** служба стартовала из обработчика медиа-уведомления
- **THEN** в журнале есть `service_started` с `source = notification`
