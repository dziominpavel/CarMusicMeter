# Design

## Context

На Teyes нет обработчика `ACTION_CREATE_DOCUMENT`, поэтому
`ActivityResultLauncher.launch` бросает `ActivityNotFoundException` и роняет
приложение. На телефоне SAF работает. Снимок уже содержит `STREAM_MUSIC`,
аудиовыходы и медиаподобные уведомления; служба пишет `boot_received`, но не
фиксирует, кем и как она запущена. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Дать рабочий способ забрать ZIP с магнитолы без SAF.
- Собрать за один выезд данные по громкости и локальному плееру.
- Сделать диагностику автозапуска однозначной.

**Non-Goals:**
- Менять источник громкости до получения данных.
- LAN-экспорт по хотспоту — отдельный change.
- Лечить автозапуск на уровне прошивки; только диагностировать.

## Decisions

### SAF сначала, Downloads как запасной путь

Экспорт остаётся SAF-first: на телефоне пользователь выбирает место, как
раньше. Запуск оборачивается в `runCatching`; при `ActivityNotFoundException`
(или другой ошибке запуска) приложение не падает, а пишет ZIP в
`Downloads/CarMusicMeter/`. Альтернатива — всегда писать в Downloads —
отклонена: на телефоне SAF удобнее и не засоряет «Загрузки».

### MediaStore вместо прямого пути

На Android 10 `MediaStore.Downloads` позволяет создать файл в «Загрузках» без
разрешения на запись. Используется `RELATIVE_PATH = Download/CarMusicMeter`,
`IS_PENDING = 1` на время записи и `0` после. Прямой путь
`/sdcard/Download` потребовал бы `WRITE_EXTERNAL_STORAGE`; `getExternalFilesDir`
менее заметен для файлового менеджера. Если `MediaStore` на Teyes недоступен,
остаётся `getExternalFilesDir` и сообщение об ошибке — это резерв на случай
совсем урезанной прошивки.

### «Поделиться» по content URI

После записи в Downloads URI можно отдать в `ACTION_SEND` с
`FLAG_GRANT_READ_URI_PERMISSION`; `FileProvider` не нужен. Это спасает, если
файловый менеджер Teyes не показывает ZIP. Если целей для share нет, файл
всё равно остаётся в «Загрузках».

### Снимок: все потоки, а не только музыка

В снимок добавляется массив потоков с именем, значением и максимумом, плюс
`isVolumeFixed`, `audioMode`, `isMusicActive`. Это позволит отличить
«STREAM_MUSIC действительно 25/25» от «крутилка управляет MCU, а Android
показывает фиксированный максимум». Источник громкости в `ListeningTracker`
пока не меняется: сначала данные.

### Кэш всех уведомлений, журнал — только медиа

`NotificationCache` хранит последние 40 уведомлений в памяти с флагом
`mediaLike`; в JSONL по-прежнему попадают только медиаподобные. Снимок
показывает все, чтобы найти локальный плеер, который постит обычное
уведомление. Данные не персистентны и попадают в ZIP только по кнопке —
компромисс между диагностикой и приватностью.

### Источник запуска службы

`WatchServiceController.start(context, source)` передаёт `manual`, `boot` или
`notification` в intent. `MediaWatchService` пишет `service_started` один раз
за запуск. При sticky-перезапуске без intent событие не пишется, чтобы не
выдумывать источник. Это вместе с `boot_received` и `service_start_failed`
даёт полную картину автозапуска.

### Play Protect — документация, не код

Play Protect блокирует самоподписанный APK с доступом к уведомлениям. Это
нормально для sideload. В `HEADUNIT_TEST.md` фиксируется: сначала пробовать
с включённой защитой; если блокирует — временно отключить проверку, установить,
включить обратно. Пер-приложенческого whitelist у Play Protect нет. После
установки приложение обычно остаётся; APK и хеш нужно сохранить.

## Risks / Trade-offs

- **MediaStore недоступен на Teyes** → сначала пробуем Downloads; при ошибке
  пишем в `getExternalFilesDir` и показываем путь. Если и это недоступно,
  остаётся share/ручной перенос.
- **Share не находит цели** → файл уже лежит в Downloads; это не блокирует.
- **Все аудиопотоки фиксированы** → громкость на Teyes недоступна через
  публичный API; зафиксируем ограничение и не будем показывать ложные данные.
- **Кэш всех уведомлений** → в памяти, 40 штук, только в ручном снимке;
  журнал не расширяется.
- **Дубли `service_started`** → пишем один раз за старт службы; повторные
  `onStartCommand` не создают новое событие.

## Migration Plan

Миграции данных нет. Новое событие `service_started` и новые поля снимка
аддитивны; старые выгрузки читаются как раньше. Откат — вернуть прямой вызов
SAF и убрать диагностические поля.

## Open Questions

Какой именно поток меняется при повороте ручки — станет видно из снимка.
Если ни один не меняется, источник громкости для Teyes потребует отдельного
change; на план этой сборки это не влияет.
