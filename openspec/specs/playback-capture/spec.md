## Purpose

Получать сведения о том, что играет в штатном плеере магнитолы, не заменяя его:
пакет, трек, исполнитель, альбом, длительность, позиция и состояние. Если плеер
не публикует MediaSession, использовать текст медиа-уведомления как резервный
источник.

## Requirements

### Requirement: Чтение активных медиасессий

Приложение MUST читать активные MediaSession через `MediaSessionManager`, когда
пользователю выдан доступ к уведомлениям. Для каждой сессии приложение MUST
сохранять имя пакета, tag сессии, название, исполнителя, альбом, длительность,
позицию, состояние, скорость, доступные actions, `mediaId`, список ключей
метаданных и наличие обложки. Приложение MUST NOT требовать root или системных
привилегий.

#### Scenario: Штатный плеер публикует сессию

- **WHEN** пользователь играет трек в штатном плеере и доступ к уведомлениям включён
- **THEN** приложение фиксирует сессию и показывает пакет, трек и позицию на экране диагностики

#### Scenario: Доступ к уведомлениям не выдан

- **WHEN** доступ к уведомлениям выключен
- **THEN** приложение MUST показывать причину `notification_access_missing` и MUST NOT падать

#### Scenario: Полный дамп по кнопке

- **WHEN** пользователь нажимает «Снять срез»
- **THEN** приложение сохраняет JSON со всеми активными сессиями, всеми ключами метаданных, состоянием, actions и аудиовыходами

### Requirement: Резервный источник — медиа-уведомления

Если плеер не публикует MediaSession, приложение MUST сохранять текст
медиа-уведомлений: заголовок, текст, `bigText`, `subText`, действия, категорию,
шаблон и наличие media session token.

#### Scenario: Плеер только уведомляет

- **WHEN** плеер не отдаёт MediaSession, но показывает медиа-уведомление
- **THEN** событие `notification` содержит пакет, заголовок и текст уведомления

#### Scenario: Уведомление обновляется

- **WHEN** плеер повторно публикует то же уведомление без изменения текста и действий
- **THEN** приложение MUST NOT писать повторное событие

### Requirement: Определение границ трека

Приложение MUST считать трек начатым, когда появляется сессия с названием,
отличным от текущего ключа, и MUST закрывать трек при смене ключа, исчезновении
сессии дольше 5 секунд или остановке службы.

#### Scenario: Пользователь переключил трек

- **WHEN** в той же сессии появляется другой трек
- **THEN** предыдущий трек закрывается событием `track_ended`, новый — `track_started`

#### Scenario: Плеер закрылся

- **WHEN** сессия исчезла и не вернулась за 5 секунд
- **THEN** трек закрывается с причиной `session_lost`

#### Scenario: Пользователь дослушал трек

- **WHEN** позиция дошла до конца трека с допуском 3 секунды
- **THEN** трек закрывается с причиной `completed`

### Requirement: Выбор сессии «сейчас играет»

Приложение MUST выбирать одну сессию из нескольких активных по приоритету:
текущий пакет в состоянии PLAYING, затем любой пакет в PLAYING, затем текущий
пакет в паузе, затем первая сессия с названием трека. Сессии без названия
MUST NOT становиться текущим треком, но MUST попадать в полный дамп.

#### Scenario: Музыка и навигация

- **WHEN** одновременно активны музыкальный плеер и навигатор
- **THEN** текущим треком становится сессия с названием, а не служебная сессия без метаданных
