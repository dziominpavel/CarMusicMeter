# CarMusicMeter

Тихий сборщик статистики прослушиваний для автомобильной магнитолы **Teyes CC3**
(Android 10) и телефона. Не заменяет штатный плеер: читает активные медиасессии,
медиа-уведомления и громкость, а результаты пишет в локальный журнал.

**Статус: v0 «пробник».** Задача этапа — выяснить, что именно отдаёт штатный плеер
Teyes, и собрать первые реальные данные. Анализ коллекции и отчёты — следующий этап
(см. `docs/ROADMAP.md`).

## Что уже умеет

- показывает активную медиасессию: пакет, трек, исполнитель, альбом, позицию, громкость;
- если штатный плеер Teyes не публикует MediaSession, читает его состояние из
  broadcast лаунчера, пользовательского уведомления и — по желанию — из
  открытого окна плеера через accessibility (только чтение);
- фиксирует реальную громкость панели через MCU Teyes (шкала 0…43, например
  `30/43`), а на телефоне — через `AudioManager`; источник громкости виден
  в событиях;
- пишет события в JSONL: старт и конец трека, пропуск, пауза, перемотка, громкость и mute;
- не разрезает трек на паузе и не создаёт фантомный трек, если служба стартовала
  при выключенном плеере;
- сохраняет полный дамп всех сессий, аудиопотоков и последних уведомлений по кнопке;
- экспортирует журнал и снимки в ZIP через системный диалог (работает и на NTFS-флешке);
  если системного диалога нет — сохраняет ZIP в `Downloads/CarMusicMeter`;
- переживает выключение зажигания: каждая пачка событий пишется с fsync, а
  текущее прослушивание сохраняется контрольной точкой раз в минуту;
- запускается после загрузки магнитолы, при появлении музыки и при открытии
  приложения; для Teyes есть отдельный пункт «CarMusicMeter (автозапуск)»;
- не имеет разрешения `INTERNET` — данные никуда не уходят;
- переживает ошибку записи: цикл не умирает молча, а показывает состояние сбора
  и число потерянных событий на экране.

## Что хранится и что попадает в экспорт

- **Журнал:** `logs/events-YYYY-MM-DD.jsonl`, append-only, fsync на каждую пачку.
- **Хранение:** по умолчанию бессрочно, с защитным лимитом **500 МБ**. При
  превышении удаляются самые старые завершённые дни; текущий день не трогается.
  Срок можно ограничить: бессрочно / 1 год / 180 / 90 дней.
- **Снимки:** `snapshots/snapshot-*.json` — при каждом экспорте и на старте
  каждого трека; хранятся 600 последних. Crash-файлов остаётся 50.
- **Экспорт:** по умолчанию вся история; пресеты 90 / 30 / 7 дней. Перед
  выгрузкой показывается число файлов по видам и объём, пустой период не создаёт ZIP.
  В `manifest.json` пишутся `range` и фактические даты `coverage`.
- Переустановка или очистка данных удаляет журнал: единственная резервная
  копия — экспортированный ZIP.

Главный экран — пульт: статус сбора, текущий трек, экспорт. Диагностика
(источники, пакет, ключи, события) — отдельный экран; настройки (доступы, батарея,
автозапуск, срок хранения) — ещё один. Период экспорта выбирается в диалоге.

Если штатный плеер не виден: включите «Чтение интерфейса» (Спецдоступ →
Спецвозможности) и добавьте приложение в автозапуск Teyes. Точный путь:
`Настройки → Пользователь → Настройки приложений → CarMusicMeter` либо
`Настройки → Общие → Автомат. включ. при запуске → CarMusicMeter (автозапуск)`.

## Быстрый старт

```bat
powershell -ExecutionPolicy Bypass -File scripts\check.ps1
build-apk.bat
```

Готовый APK появится в `dist\CarMusicMeter-release-latest.apk` (и копия в `dist\archive\`).
Для отладочной сборки с читаемыми стектрейсами: `build-apk.bat debug`.

Установка на магнитолу и проверка в машине — `docs/HEADUNIT_TEST.md`.
Для проверки на телефоне: `build-apk.bat debug install` (нужен adb).

## Анализ выгрузки

```bat
py scripts/report.py CarMusicMeter-<id>-logs-<дата>.zip
py scripts/report.py export-1.zip export-2.zip --csv report.csv --json-out report.json
```

Отчёт считает прогресс и прослушанное время, скипы, громкость, перемотки и
кандидатов на удаление. Несколько ZIP можно передать сразу — журналы
склеиваются без дублей. Формулы и ограничения — `docs/METRICS.md`.

## Как это работает

```
штатный плеер Teyes / Яндекс.Музыка
   │  MediaSession / titlesReceiver / уведомление / accessibility
   ▼
NotificationWatchService ──► NotificationCache
   │
MediaWatchService (foreground, опрос 0.5–1 с)
   ├─ MediaSessionProbe ──► ListeningTracker ──► EventLog (JSONL + fsync)
   └─ AudioManager (STREAM_MUSIC) ─┘
                                        │
                                 «Экспорт логов» (SAF)
                                        ▼
                                   ZIP на флешку
                                        ▼
                                анализ на ПК (v1+)
```

Подробности, схема событий и эвристики — `docs/ARCHITECTURE.md`.

## Структура

- `app/src/main/java/com/example/carmusicmeter/` — код
  - `service/` — foreground-служба и NotificationListener
  - `data/` — трекер, журнал, состояние
  - `probe/` — чтение MediaSession и дамп
  - `diagnostics/` — снимки и crash-лог
  - `ui/` — экран диагностики
- `openspec/specs/` — требования к захвату, громкости и журналу
- `docs/` — архитектура, метрики, проверка в машине, план, версионирование
- `scripts/check-version.py` — сверка версии и changelog
- `scripts/report.py` — отчёт по ZIP-выгрузке на ПК

## Приватность

Всё хранится в приватной папке приложения на устройстве. Сеть не используется.
Экспорт — только вручную, в выбранный пользователем файл.
