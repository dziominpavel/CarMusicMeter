## Почему в фоне нет треков

Snapshot в 15:57:12:

```json
"sessions": [],
"notifications": [],
"stockPlayer": {
  "package": "com.syu.music",
  "source": "accessibility",
  "durationMs": null,
  "positionMs": null
}
```

То есть одновременно:

1. **MediaSession нет.** `sessions` пуст, хотя музыка играет (`isMusicActive=true`).
2. **Медиа-уведомления нет.** `notifications` пуст; штатный плеер не постит ongoing-уведомление.
3. **FYT broadcast не приходит.** За сессию нет ни одного события с `source=fyt_broadcast`.
   Receiver на `titlesReceiver` зарегистрирован, но плеер его не вызывает.

По сообществу FYT штатный `com.syu.music` отправляет интенты не broadcast-ом «всем», а
адресно конкретным пакетам (например, `com.ava.car`, `cn.teyes.online` — лаунчеру).
Обычное приложение такой интент перехватить не может. Это объясняет, почему
`titlesReceiver` молчит.

Остаётся accessibility, а он читает только активное окно:

```kotlin
val root = rootInActiveWindow ?: return
if (root.packageName?.toString() != packageName) return
```

Когда активно наше приложение или навигатор, `rootInActiveWindow` — не `com.syu.music`,
поэтому сканирования нет. Это не баг разрешений, а граница доступных источников.

### Что можно улучшить в фоне

- **Split-screen.** Если плеер виден рядом с навигатором, `getWindows()` может содержать
  окно `com.syu.music`, даже когда фокус у навигатора. Сейчас сервис смотрит только
  `rootInActiveWindow`. Перебор окон может дать треки в split-screen.
- **Полный фон.** Если плеер полностью закрыт навигатором, окна нет. Без MediaSession,
  уведомления, broadcast или системного API трек не получить. Это фундаментальное
  ограничение текущего пути.

## Ложные треки и ложные скипы

### 1. Транзиентный «Список»

```
15:47:35.413 track_started  title="Список" artist="1763. Tina Turner - The Best.flac"
15:47:35.968 track_ended    playedMs=555 endReason=not_played
15:47:35.968 track_started  title="The Best.flac" artist="Tina Turner"
```

В момент открытия плеера UI ещё не стабилизировался, парсер взял первую строку
(`Список`) и следующую строку списка как исполнителя. Через 0.5 с состояние исправилось.
Мусорное событие попало в журнал, но хотя бы попало в `not_played`.

### 2. Экран папки как трек на 88 секунд

```
15:48:36.867 track_started  title="Внутренняя память" artist="Список музыки"
15:50:04.860 track_ended    playedMs=87994 endReason=skipped
```

В этот момент пользователь был в списке файлов, а музыка продолжала играть.
Парсер принял заголовок папки за трек. Реальный трек `Can't Help Falling in Love`
был закрыт через 7.7 с как `skipped`, хотя музыка играла ещё ~88 секунд.
Это и потеря реального прослушивания, и лишний фейковый трек в статистике.

### 3. Строки списка

В `rawTexts` видны строки вида:

```
1763. Tina Turner - The Best.flac
1764. Tinie Tempah - ...
```

Парсер не отличает строку списка от строки «сейчас играет». Иногда он берёт
`1763. Tina Turner - The Best.flac` как исполнителя, иногда — как трек.
Нужна уверенность: строка «сейчас играет» имеет формат `Artist - Title.ext`
и не начинается с номера.

### 4. Расширение в названии

`cleanTitle()` снимает расширение только если в строке есть `/` или `\`.
Для `The Best.flac` расширение остаётся. В ключах треков появляется:

```
com.syu.music::the best.flac::tina turner
com.syu.music::список::1763. tina turner - the best.flac
```

Это затруднит сопоставление с библиотекой и раздует отчёт.

## Метрики: почему 100% скипов

`track_ended` для accessibility:

| Время | Трек | played | duration | reason |
|---|---|---:|---:|---|
| 15:48:20 | No Hard Feelings | 44 с | null | skipped |
| 15:48:29 | Reality | 6.6 с | null | skipped |
| 15:48:36 | Can't Help Falling in Love | 7.7 с | null | skipped |
| 15:50:04 | Внутренняя память (фейк) | 88 с | null | skipped |
| 15:53:26 | 22 (Cotis) | 201 с | null | skipped |
| 15:54:23 | Perfect Paradise | 56 с | null | skipped |

В `ListeningTracker`:

```kotlin
val completed = duration != null && (...)
val reason = when {
    completed -> "completed"
    playedMs < 3000 -> "not_played"
    ...
    next.packageName == active.snapshot.packageName -> "skipped"
}
```

`duration` у accessibility всегда `null`, поэтому `completed` не может стать `true`.
Любой переход на другой трек того же пакета — `skipped`. Даже если трек реально
доиграл до конца. Отсюда `completed=0`, `skip_rate=100%` для штатного плеера.

Отчёт по всей выгрузке:

```
Закрытых: 21 · оценённых: 17 · completed: 0 · skipped: 17 · открытых: 2
```

17 скипов — это смесь реальных ручных переключений (вы тестировали) и структурного
бага с `duration=null`. Как метрика `skip_rate` сейчас недостоверна.

## Громкость: смена источника посреди трека

В 15:52:05 и 15:53:05 `track_progress` показывает:

```
volume=25 volumeMax=25
```

А в 15:51:05 было `3/43`, в 15:54:04 снова `3/43`. То есть на две минуты
MCU-громкость пропала, и приложение перешло на `AudioManager` (25/25).
В `track_ended` для `22 (Cotis)`:

```
volumeStart=25 volumeEnd=25 volumeLow=25 volumeHigh=25 volumeChanges=0
```

Хотя до этого было 11 изменений MCU. Причина — в `ListeningTracker.onVolume`:

```kotlin
if (previousSource != null && previousSource != source) {
    ...
    active?.let {
        it.volumeStart = volume
        it.volumeLow = volume
        it.volumeHigh = volume
        it.volumeChanges = 0
    }
    return emptyList()
}
```

Смена источника:

- не пишет событие;
- сбрасывает историю громкости трека;
- смешивает шкалы 0–43 и 0–25.

В логе нет `teyes_toolkit` с `available=false`, поэтому причина падения MCU не видна.
Нужно событие `volume_source_changed` с причиной (нет модуля, stale, ошибка чтения)
и раздельная статистика по источникам.

## Что делать дальше

### Приоритет 1 — не терять реальные прослушивания

1. Парсер accessibility должен принимать только уверенные состояния:
   - строка `Artist - Title.ext`, не начинающаяся с номера;
   - либо `Title.ext` + соседняя строка исполнителя;
   - заголовки папок (`Список`, `Внутренняя память`, `Список музыки`) и строки
     списка (`^\d+\.\s`) игнорировать, сохраняя последний известный трек;
   - debounce 0.8–1.0 с, чтобы переходный UI при открытии плеера не создавал трек.
2. Снимать расширение `.flac/.mp3/...` в `cleanTitle()` всегда, а не только для путей.
3. При потере окна плеера не выдавать последний трек за новый: писать
   `capture_gap`/`source_lost`, чтобы в отчёте было видно «здесь данных нет».

### Приоритет 2 — вернуть корректный `completed`

Нужно понять, отдаёт ли UI плеера позицию/длительность. В `rawTexts` они отфильтрованы
(`TIME` regex), а `SeekBar.rangeInfo` сервис вообще не читает. Следующий диагностический
билд должен писать:

- все видимые тексты без фильтра;
- `className`, `viewIdResourceName`, `contentDescription`, `rangeInfo` для узлов плеера;
- список окон `getWindows()` с пакетами и активностью.

Если время/SeekBar есть — `durationMs` и `positionMs` можно получать напрямую, и
`completed` станет честным. Если нет — окончания accessibility без длительности
надо помечать `unknown` и не включать в `skip_rate`/`completion`.

### Приоритет 3 — split-screen и фон

- Перебирать `getWindows()` и искать окно `com.syu.music`, а не только
  `rootInActiveWindow`. Это может дать треки, когда плеер виден в split-screen.
- Проверить в машине: навигатор + плеер в split-screen, затем полный экран навигатора.
- Если полный фон не даёт окна — зафиксировать ограничение в спеке и UI:
  «штатный плеер в фоне не читается; нужен MediaSession/уведомление/прокси».
- Экзотические пути (подмена package name, прокси-лаунчер, toolkit-модуль `music`)
  не трогать в v0: высокий риск, мало данных.

### Приоритет 4 — гигиена громкости

- `volume_source_changed` при переходе MCU ↔ AudioManager.
- Не сбрасывать историю трека молча; хранить диапазоны по источникам.
- В `track_started/ended/progress` всегда писать `volumeMax` и `volumeSource`.
- `teyes_toolkit` — только при смене состояния, не на каждое значение.

## Рекомендуемый следующий шаг

Сделать один диагностический change:

1. Исправить парсер и ключи (безопасно, покрывается JVM-тестами).
2. Добавить `volume_source_changed` и per-source статистику.
3. Добавить диагностику UI-дерева/`rangeInfo`/`getWindows()`.
4. В отчёте разделить `skipped` и `unknown` для accessibility без длительности.

После этого — одна поездка: открыть плеер, свернуть его, включить навигатор,
проверить split-screen, паузу, mute и естественное окончание трека. По новому ZIP
будет видно, есть ли у UI позиция/длительность и видно ли окно плеера в фоне.
